# Prompts para Gemini Orquestador en Antigravity

## 1. Alex · crear una única base compartida
Actúa como orquestador de la preparación del backend de Olimpyc Fit. Verifica origin, estado local y rama. Trabaja en feat/backend-alex. Lee AGENTS.md, el plan, el contrato y el modelo desde origin/main si aún no aparecen en tu rama. Conserva cualquier cambio previo. Inspecciona el backend existente antes de añadir archivos. Si delegas, asigna archivos disjuntos y reserva los archivos compartidos a un solo editor.

Prepara únicamente backend/ con Node.js, Express y npm. Organiza el punto de entrada y la aplicación por separado, configuración por entorno y capas de rutas, controladores y servicios. Deja una ubicación documentada para repositorios de datos, migraciones PostgreSQL en Supabase y el módulo de planificación de Samuel. Crea solo archivos útiles, documenta las carpetas futuras y evita stubs de negocio. Incluye scripts de desarrollo y arranque, lockfile, README de backend y .env.example con valores ficticios. Si hace falta excluir secretos, usa backend/.gitignore. Deja GET /api/v1/health como única ruta técnica, arranque sin credenciales externas y 404 JSON. Usa la convención de módulos existente o escoge una sola para todo el backend.

El alcance termina en la estructura. Reserva para otras tareas las tablas, las políticas, el login, las suscripciones, los endpoints funcionales y las llamadas a DeepSeek. Trabaja exclusivamente dentro de backend/. Hellen ya tiene frontend/ en local. Ejecuta el arranque y comprueba health y 404. Revisa el diff, informa archivos, resultados y pasos para Samuel. Entrega los cambios en tu rama para revisión hacia develop.
 
## 2. Samuel · preparar su módulo después de integrar la base
Trabaja en feat/ia-samuel. Lee las instrucciones en origin/main, el contrato y la especificación del asistente. Comprueba que la base de Alex ya está integrada en origin/develop y actualiza tu rama conservando su historial y cambios locales. Si aún falta, informa el commit o dependencia requerida. Usa la estructura y convención de módulos existentes.

Dentro de la carpeta de planificación acordada con Alex, prepara únicamente su estructura mínima y un README que identifique las entradas de evaluación y catálogo, el futuro adaptador servidor para DeepSeek, la validación del borrador y la aprobación humana. Documenta cómo se distinguirán V1 y V2 y quién publica. Evita paquetes, rutas o archivos vacíos sin consumidor. La configuración global, el registro común de rutas y las migraciones pertenecen a Alex. El frontend pertenece a Hellen. Conserva las claves fuera de Git. Verifica que sigue arrancando el backend y que tu diff queda limitado al módulo. Devuelve el listado de cambios y los puntos de integración pendientes, sin implementar la funcionalidad.
